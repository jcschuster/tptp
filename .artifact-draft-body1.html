Report to the TPTP maintainers

SyntaxBNF v9.3.1.2 Findings

Nineteen items found by generating a parser mechanically from the published BNF and running it over every file of TPTP v9.3.1: a release that ships an out-of-date copy of its own grammar, four library files the grammar refuses, two vocabularies the library has outgrown, a block of twenty-six rules nothing can reach, three ambiguities, four points where the prose and the productions disagree, four typos, and three notes on the SZS ontology page.

Source SyntaxBNF-v9.3.1.2 Library TPTP v9.3.1, all 29,358 files Method LALR(1) parser generated from the BNF

Scope and method

Every rule of SyntaxBNF-v9.3.1.2 was translated mechanically into a yecc grammar — no hand-written productions — and the resulting parser was run over a complete TPTP v9.3.1 install. Nothing below is a stylistic objection. Each item is one of four things: a file in the library that the published grammar refuses, a rule in the grammar that nothing can reach, a place where the BNF's prose and its own productions disagree, or a place where two published documents disagree with each other.

F1releaseTwo grammars in circulation

The v9.3.1 release ships a v9.3.0.4 SyntaxBNF

TPTP-v9.3.1 Documents/SyntaxBNF · against the file served at tptp.org

The distribution carries its own copy of the grammar. That copy's header ends where the served file's header begins, and the two files differ in a rule rather than only in comments.

EffectAn implementer who takes the grammar from the tarball and an implementer who takes it from the website build different parsers, and neither has any way to notice. The shipped one rejects the first-order functional style in THF that v9.3.1.1 was written to allow.
SuggestedShip the current file in the release, and put the BNF revision number where a reader will see it — in Documents/ReadMe, or as a line in the file that names the TPTP release it belongs to. Today neither document names the other.
F2::=Blocks parsing

<source> no longer admits theory(...), so SYN000*2.p does not parse

SyntaxBNF-v9.3.1.2 lines 506–514 · SYN000-2.p, SYN000+2.p, SYN000_2.p, SYN000^2.p

The comment above the rule records that <source> used to be <general_term>. Expanding it into a fixed list of alternatives dropped the ability to write a functional term in source position, and theory(equality) is exactly that.

Under the pre-expansion rule these parsed as <general_term> → <general_data> → <general_function>. The word theory survives in the BNF only as an <intro_type> value on line 521, which is a different position entirely.

EffectEight statements in four files, and they are the whole of it: across all 29,358 files these are the only occurrences of theory(...) in source position, and these four are the only files in the library the published grammar refuses. They are also SYN000*2 — the annotated-formula demonstration, written once in CNF, once in FOF, once in TFF and once in THF. A parser generated from the BNF cannot read the language's own worked examples, in any dialect.
SuggestedRestore theory(<theory_name>) as an alternative of <source>, or keep <source> ::= <general_term> as the syntactic rule and express the expansion as :==.
F3:==350 files

logic is missing from the <formula_role> list

SyntaxBNF-v9.3.1.2 lines 59–62 · 350 problems across ten domains

Counting every role in every annotated formula of the library gives eleven distinct values: axiom 40,516,753, type 4,947,954, negated_conjecture 187,888, hypothesis 77,086, definition 71,175, lemma 41,129, conjecture 17,241, logic 350, and four each of unknown, theorem and assumption. Ten of the eleven are in the :== list.

EffectAny tool checking roles against the published list reports 350 conforming library problems as carrying an unknown role. logic is the only role in use anywhere in the library that the :== list does not name.
SuggestedAdd logic to the <formula_role> :== list. See F5 — the same omission runs deeper.
F4:==Five systems, 76 uses

<ntf_modal_system> is short by five systems

SyntaxBNF-v9.3.1.2 lines 345–346 · 76 problems in GRA, LCL, PHI, PLA, SYO and SYP

Counting only occurrences outside comments, the library uses eleven modal systems where the BNF names six.

Two further names appear only inside problem headers, so they are never parsed but do suggest the list is short by more than five: $modal_system_S5U in 26 files and $modal_system_T in 17.

Effect76 live uses of a modal system the grammar does not define, one per file, spread across six domains — SYP 54, PHI 8, GRA 4, LCL 4, PLA 3 and SYO 3. Meanwhile $modal_system_B, which the list does name, is used once in the entire library.
SuggestedExtend the list, or say in the BNF that it is illustrative rather than closed. If the modal-system names are open-ended, that is worth stating explicitly, because every other :== list in the file is closed — and because the other four ntf vocabularies are not short: $domains, $designation, $terms, $modalities and their values ($constant, $varying, $cumulative, $decreasing, $rigid, $flexible, $local, $global) are used some 2,000 times between them and every use is in the BNF.
